# 技術選定

GitHub Pages(静的ホスティング)で動かすことを前提にした選定と、その理由。

## 構成

| 役割 | 採用 | ライセンス | 理由 |
| --- | --- | --- | --- |
| 言語 | TypeScript | Apache-2.0 | シミュレーションのロジックが複雑になるため型の恩恵が大きい |
| ビルド | Vite | MIT | 静的ファイルをそのまま出力でき、Pages へのデプロイ手順も公式に用意されている |
| 描画 | PixiJS v8 | MIT | 大量のパケット描画に強く、WebGL / WebGPU に対応。ゲームエンジンではなく描画ライブラリなので、自前のシミュレーションと組み合わせやすい |
| グラフ | uPlot | MIT | 軽量で時系列に特化。p99・エラー率の推移表示に使う |
| UI パネル | 素の DOM | — | HUD・ツールバー・モーダル程度なので、現時点ではフレームワーク不要。複雑になったら Preact(MIT)を検討 |
| テスト | Vitest | MIT | シミュレーションを描画から切り離してユニットテストする |
| ライセンス確認 | rollup-plugin-license | MIT | 依存のライセンスをビルド時に検査し、`THIRD_PARTY_LICENSES.txt` を自動生成する |
| デプロイ | GitHub Actions(公式 Pages ワークフロー) | — | `gh-pages` ブランチ運用より管理が楽 |

### 見送ったもの

- **Phaser**(MIT): 完成度の高いゲームエンジンだが、本作はシミュレーションとエディタ操作が中心で、物理やシーン管理の多くを使わない
- **Konva**(MIT): ドラッグや接続線などエディタ的な操作は楽だが、数千個のパケットを流す描画性能では PixiJS に劣る
- **Three.js**(MIT): 3D 表現は不要

## GitHub Pages の制約と対応

| 制約 | 対応 |
| --- | --- |
| サーバー処理なし | セーブは localStorage、構成の共有は JSON を URL ハッシュにエンコード |
| `kota395.github.io/packet-factory/` のようにパスが付く | Vite の `base: './'`(相対パス)で、公開先が変わってもそのまま動くようにした |
| レスポンスヘッダーを設定できない(COOP/COEP 不可) | SharedArrayBuffer やマルチスレッド WASM は使わない。通常の Web Worker は使える |
| プライベートリポジトリの Pages は有料プランが必要 | ワークフローは `DEPLOY_PAGES` 変数が `true` のときだけ公開する。それまではテストとビルドだけ回す |

## ライセンス方針

- **コードの依存**: MIT / Apache-2.0 / BSD-2-Clause / BSD-3-Clause / ISC / 0BSD に限定する。
  `vite.config.ts` の `ALLOWED_LICENSES` で強制しており、これ以外(GPL / AGPL や不明なもの)がバンドルに入るとビルドが失敗する
- **著作権表示**: MIT なども表示義務があるため、ビルド時に `dist/THIRD_PARTY_LICENSES.txt` を生成して一緒に公開する
- **素材**: フォントは OFL(Noto Sans など)、アイコンは MIT / CC0、効果音は CC0 を基本にする。
  CC BY-NC(非商用限定)や出典不明の素材は使わない。現時点では外部素材なし(フォントはシステムフォント)
- **本作自体のライセンス**: 未定。公開前に決める

## アーキテクチャ

```
src/
  sim/       描画に依存しないシミュレーション(テスト対象)
    config.ts      ノード性能・経済・トラフィックなどの調整値
    simulation.ts  固定刻みの待ち行列シミュレーション
    metrics.ts     レイテンシのヒストグラム、可用性、履歴
    layout.ts      構成の保存・共有(URL ハッシュ / localStorage)
  render/    PixiJS による盤面描画(シミュレーションを読むだけ)
  ui/        DOM の HUD・グラフ
  main.ts    入力・ゲーム進行のつなぎ込み
tests/       Vitest
```

- シミュレーションは 10ms 刻みの離散時間モデル。描画側は毎フレーム状態を読むだけなので、早送りや将来の Web Worker 化がしやすい
- シード付き乱数を使っているため、同じ構成・同じシードなら結果が再現する
