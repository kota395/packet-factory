# packet-factory

データセンター/ネットワークを題材にした、ブラウザで遊べるインクリメンタルゲーム。
小さな Web サービスを運営し、稼いだお金を投資してインフラとユーザーを育てていく。
GitHub Pages などの静的ホスティングだけで動く。

**遊ぶ: https://kota395.github.io/packet-factory/**

> ステータス: インクリメンタル版(拡張の段階 1〜6: CDN / LB / WEB / キャッシュ / DB / リードレプリカ / シャーディング、データ量と帯域、配信コンテンツ 2 種)
>
> 拡張の段階の考え方は [docs/scaling.md](docs/scaling.md)、技術選定とライセンス方針は [docs/tech-stack.md](docs/tech-stack.md) を参照。

## 遊び方

- ユーザー数 × 0.01 がリクエスト流量(rps)になり、捌けた分だけ収入になる
- **投資**で広告(市場規模の拡大)・収益化(単価アップ)・スケールアップ(WEB / DB の高性能化、回線増強)・新機能の解放ができる
- 捌ききれずエラーや遅延が増えるとユーザーが離脱する。詰まってきたら WEB や DB を増設する
- リクエストにはデータ量がある。**画像投稿・動画配信**を導入すると単価は上がるがデータが重くなり、LB の帯域が詰まりやすくなる(投資メニューでオン/オフできる)
- 同じ種類のノードは買うたびに 15% ずつ高くなる。維持費もかかる
- ページを閉じている間も、直前の収支の 50% を最大 8 時間分受け取れる
- 進行はブラウザに自動保存される。別の端末へはセーブメニューのセーブコードで移せる

### 操作

- 下のツールバーでノードを選び、空きマスをタップして配置する
- ノードはドラッグで空いているマスへ移動できる(接続はそのまま)
- 「接続」で接続元 → 接続先の順にタップしてつなぐ(同じ線をもう一度つなぐと解除)
- ノードをタップすると、受信量・内訳・送り先ごとの流量・上限と余裕・帯域・キュー・エラーの内訳・維持費などが詳細パネルに出る
- ノードの数字は「届いている量 / 捌ける上限」(rps)。バーが黄色・赤になったら増設や強化の合図
- 接続できる向き: NET → CDN / LB / WEB、CDN → LB / WEB、LB → WEB、WEB → キャッシュ / DB / レプリカ、キャッシュ → DB / レプリカ、DB → レプリカ
- LB と CDN はサービス(NET)1 つにつき 1 台。帯域は投資の回線増強で増やす

### 拡張の段階

投資メニューは段階ごとにまとまっている。詳しくは [docs/scaling.md](docs/scaling.md)。

| 段階 | 詰まる所 | 打ち手 |
| --- | --- | --- |
| 1. 1 台構成 | WEB の CPU | WEB スケールアップ(上限 Lv6) |
| 2. 水平分散 | WEB の台数 → LB の帯域 | LB を置いて WEB を並べる、LB 回線増強 |
| 3. データ層の分離 | DB(正本なので 1 台) | DB スケールアップ(上限 Lv8) |
| 4. 読み込みの分散 | DB の読み込み | キャッシュ(当たれば返す)、リードレプリカ(DB から複製を受けて読み込みを処理) |
| 5. 重いコンテンツ | 帯域 | 画像・動画で単価アップ、CDN で静的を手前から返す |
| 6. 書き込みの分散 | DB の書き込み | シャーディングで DB(プライマリ)を増やす |

- 会員機能を解放すると、利用者のリクエストの 1/5 がデータを使う(8 割が読み込み、2 割が書き込み)。CDN はこれらをキャッシュできない
- WEB にデータ層がつながっていなければ、読み込み・書き込みも WEB が静的として返す(単価が下がるだけでエラーにはならない)
- 読み込みはつながっている先のうち キャッシュ > レプリカ > DB の順に優先して送られる。書き込みは DB だけが受ける
- レプリカは DB からつないでおかないと使われない。DB の書き込みをすべて反映するので、書き込みが多いとレプリカも忙しくなる
- 速度は一時停止 / 等速 / 2 倍 / 4 倍

### 進行の目安(バランス確認ボットの結果)

| 時間 | 出来事 |
| --- | --- |
| 4〜5 分 | ロードバランサー解放、WEB を増設していく |
| 12 分前後 | 会員機能。DB を置くと読み込み・書き込みが流れ始める |
| 16 分前後 | 画像投稿、キャッシュ |
| 20 分前後 | リードレプリカ、CDN |
| 25〜30 分 | シャーディング、動画配信 |
| 45 分〜 | シャードとレプリカを増やしながら拡大。LB の接続先(WEB 64 台)が次の壁 |

## 開発

```sh
npm install
npm run dev      # 開発サーバー
npm test         # シミュレーションのユニットテスト
npm run build    # 型チェック + dist/ へビルド(依存ライセンスの検査込み)
npm run preview  # ビルド結果の確認
npm run balance  # バランス確認ボット(BOT_MIN=20 などで時間指定)
```

### 調整値の場所

| 調整したいもの | 場所 |
| --- | --- |
| **価格まわり**(初期資金、全体の物価、ノード・解放・強化の初回価格と増加倍率、維持費、撤去の返金率) | `src/sim/pricing.ts` |
| ノードの性能・帯域・キャッシュ・台数の上限 | `src/sim/config.ts` の `NODE_DEFS` |
| データを使うリクエストの割合・読み書きの比 | `src/sim/config.ts` の `DATA_ACCESS` |
| 1 件あたりのデータ量(基準) | `src/sim/config.ts` の `DATA_SIZE_KB` |
| 回線の送信待ちの上限(超えたら捨てる) | `src/sim/config.ts` の `LINK_BUFFER_MS` |
| ユーザーの増え方・離脱 | `src/sim/config.ts` の「ユーザーとトラフィック」と `CHURN` |
| 1 件あたりの収益(基準) | `src/sim/config.ts` の `BASE_REVENUE` |
| 放置収入 | `src/sim/config.ts` の `OFFLINE` |
| 解放の内容、画像・動画の単価とデータ量の倍率 | `src/sim/economy.ts` の `UNLOCKS` |
| 強化の効果・対象・レベル上限 | `src/sim/economy.ts` の `UPGRADES` |
| 段階の分け方と説明 | `src/sim/economy.ts` の `STAGES` |

価格は「n 回目の価格 = first × growth^n × PRICE_SCALE」で決まる。
変えたら `npm run balance` のログで節目の時刻を見比べる。

ノードの振る舞いは種類ごとの分岐ではなく、`NODE_DEFS` の項目(受け付ける種類、キャッシュ、帯域、振り分けの優先度、複製など)の組み合わせで決まる。
新しいノードは定義と価格を足せば動き、強化も `target`(対象ノードと能力)を書けば効く。
新しい配信コンテンツは `UNLOCKS` に `effect`(種類ごとの単価・データ量の倍率)を付けて足すだけで、オン/オフの切り替えや投資メニューの表示も自動で付く。

### GitHub Pages で公開する

1. リポジトリの Settings → Pages で Source を「GitHub Actions」にする(設定済み)
2. `main` に push すると、テスト・ビルドのあと自動で公開される

PR ではテストとビルドだけを実行する。

## コンセプト

工場ゲームの「ベルトコンベアと加工機」を「ネットワーク経路とサーバー群」に置き換え、
インクリメンタルゲームの「稼ぐ → 投資する → もっと稼ぐ」の成長ループと組み合わせたもの。

- 投資でユーザーを増やすほど流量が増え、インフラが追いつかないと離脱で頭打ちになる
- つまり「市場を広げる投資」と「捌く力への投資」のバランスが常に問われる
- 常に **スループット / レイテンシ / コスト** の 3 つがトレードオフになる

## 今後の候補

### コンポーネント

| ノード | 役割・特性 |
| --- | --- |
| メッセージキュー + ワーカー | 動画の変換など重い処理をリクエストの外へ逃がし、バーストを吸収する(遅延は増える) |
| オブジェクトストレージ | 画像・動画の実体を WEB から切り離し、CDN の取得元にする |
| 複数の LB / リージョン | LB の接続先の上限や、リージョン障害を越えるための次の段階 |
| WAF / ファイアウォール | 攻撃トラフィックを落とす(誤検知もある) |
| 上位機種 | 同じマスでより高性能なサーバー(盤面が埋まった後の伸びしろ) |

### リクエストの種類

- 🟢 API 読み込み: キャッシュが効くとは限らない
- 🟣 重いバッチ: キューに逃がすのが正解
- 🔴 攻撃・ボット: 通すと他のリクエストを巻き込む

### イベント・障害

- バズによるトラフィック急増、DDoS 攻撃
- サーバー故障(冗長化していないと全停止)、リージョン障害
- キャッシュ全消し(コールドスタート)
- 機器の EOL(古い機材が使えなくなり移行が必要)

### 進行

- 転生: 会社を売却してリセットし、永続ボーナスを得る
- 個人ブログ → EC サイト → SNS → 動画配信 → グローバルサービス のように事業を広げる
